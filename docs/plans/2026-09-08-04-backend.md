# Fugugent Backend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** An API that gives the frontend agent data for four categories, fast and **never empty**, even while 8004scan is down.

**Architecture:** Hono + Postgres (Drizzle) + Redis. Four layers: a BFF to 8004scan with cache and circuit breaker; an on-chain indexer as the safety net; a four-category classifier; the marketplace API. Every data source has a tiered fallback.

**Tech Stack:** TypeScript, Hono, Drizzle, Postgres, Redis, viem, vitest.

**Spec:** `docs/specs/2026-09-08-fugugent-design.md` §6 · **API research:** `docs/research/04-8004scan-termix-pancakeswap.md`

## Global Constraints

- **Every 8004scan call must carry a browser `User-Agent`.** Without it the API returns HTTP 500, not 429 — verified live. The same applies to dGrid (it returns 403).
- **The API key never touches the browser.** The frontend only talks to our backend.
- **Tiered fallback is mandatory:** 8004scan → Postgres cache → on-chain read → curated seed. The marketplace must never be empty when the judges look at it.
- Exponential backoff retry 3–5×, a circuit breaker per source. The upstream is proven to return intermittent `500 DATABASE_ERROR` — 4 of 5 attempts failed during research.
- Cache TTL: agent detail 60s · leaderboard 5m · trending 1m · global 60s.
- All on-chain values as `bigint`; never use `number` for money.
- Without an API key, the anonymous tier gets only 30 req/min — the architecture must still be correct without a key, and automatically get more headroom once `SCAN8004_API_KEY` is set.
- Commands are run from `backend/`.

### Task 1: Foundation — config, a resilient HTTP client

**Files:** `package.json`, `tsconfig.json`, `vitest.config.ts`, `src/config.ts`, `src/http/client.ts`, `src/__tests__/client.test.ts`

**Produces:**
- `loadConfig()` → testnet contract addresses, RPC, base URL, optional API key
- `createHttpClient({ fetchImpl, now })` → `get(url, opts)` with retry, timeout, circuit breaker
- `class UpstreamError extends Error` carrying `status` and `attempts`

**Binding rules:**
- The browser `User-Agent` header is **always** sent. There is a test that enforces this; without the header the request is considered broken.
- Retry on 5xx status codes and network failures; do **not** retry on 4xx other than 429.
- Circuit breaker: after N consecutive failures, fail fast for a cooldown, then allow one probe attempt.
- `fetchImpl` and `now` are injected — tests never touch the network.

Required tests: the User-Agent is always present; a 500 is retried and then succeeds; a 404 is not retried; the breaker opens after the threshold; the breaker allows a probe after the cooldown; a timeout produces an `UpstreamError`.

### Task 2: The 8004scan source + the on-chain source

**Files:** `src/sources/scan8004.ts`, `src/sources/onchain.ts`, a test for each

**Produces:**
- `listAgents({ chainId, limit, offset, filters })`, `semanticSearch(q, opts)`, `getAgent(chainId, tokenId)`
- `readFuguListings()` reading `FuguRegistry` on testnet (`0xb2f36070E6eae3353E8e755172B477DF213ae248`), `listingCount()` and `getListing(id)`
- A normalizer that turns both response shapes into a single `AgentRecord` type

**Rule:** the 8004scan response shape is **not uniform** (`{items}` vs `{success,data}` vs `{success,error}`) — the normalizer must handle all three and must not throw on an unknown shape, but instead return an empty list and mark the source unhealthy.

Tests: the normalizer for all three shapes; the spam filters (`is_registered`, `min_score`, `has_a2a`) are actually sent as query parameters; the on-chain read uses the address from config.

### Task 3: DB schema + tiered cache

**Files:** `src/db/schema.ts`, `src/db/repo.ts`, tests

**Produces:** tables `agents`, `agent_categories`, `source_health`; `upsertAgents()`, `getCachedAgents(filter)`, `recordSourceHealth()`

**Rule:** the cache stores `fetchedAt`; readers know the age of the data and return it alongside the result, so the UI can honestly show "data is N seconds old" instead of pretending it is fresh.

### Task 4: The four-category classifier

**Files:** `src/classify.ts`, tests

**Produces:** `classify(agent): { category: Category | null; confidence: number; reason: string }`

**Rule:** pure, no I/O. The first layer is keywords over name/description/tags; the second layer is the OASF skill/domain when present. Return `null` when confidence is below the threshold — it is better not to categorize than to categorize wrongly. Categories: `REBALANCING`, `GRID`, `YIELD`, `HEALTH_FACTOR`.

Tests: every category has at least three positive examples and one negative; an unclear agent produces `null`.

---

### Task 5: The service with tiered fallback

**Files:** `src/service/agents.ts`, tests

**Produces:** `getAgentsByCategory(category, opts)`, `getAgentDetail(id)`, `getHealth()`

**Binding rules — this is the core of what the judges score:**
1. Try 8004scan.
2. If it fails or the breaker is open → the Postgres cache, marked `stale`.
3. If the cache is empty → read on-chain (`FuguRegistry`).
4. If it is still empty → a curated seed from a file.
The result **always** carries `source` and `ageSeconds`, so the UI and the judges know where the numbers came from.

Tests: all four fallback levels are triggered in order with injected sources; `source` is correct at each level; it never throws to the caller.

### Task 6: HTTP endpoints + health

**Files:** `src/routes/agents.ts`, `src/routes/health.ts`, `src/index.ts`, tests

**Endpoints:** `GET /api/agents?category=&limit=&offset=`, `GET /api/agents/:id`, `GET /api/categories` (count per category), `GET /api/health` (status of each source, honestly).

**Rule:** `/api/health` shows the real state of every source, including the ones that are down — this is what makes our resilience claim checkable rather than merely stated.
